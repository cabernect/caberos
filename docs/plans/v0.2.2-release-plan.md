## Product Promise

An agent can create polished, natively editable PowerPoint presentations,
browser-native HTML presentations, styled Word documents, and Excel workbooks
with real formulas, tables, and charts. It can safely edit supported uploaded
Office files, inspect their appearance, and improve them through conversation.
The operator can review pages, slides, and sheets inside CaberOS, request a
targeted revision, and retrieve any earlier version.

Representative request:

> Create an eight-slide market-analysis presentation and a companion report
> using the supplied data and brand assets. Keep the deck editable in PowerPoint.
> Show me both in CaberOS. Then simplify slide 4 and revise the report's summary
> without changing the underlying figures or losing the originals.
> Also create an HTML deck with live transitions for browser presentation.
> Style the uploaded XLSX, add calculated columns using real Excel formulas,
> and build a summary sheet/chart without losing the original workbook.

This release improves the existing Artifact Studio and shared preview module.
It is not a new canvas editor, an Office replacement, or an agent-authored app.

## Confirmed Direction

- Prioritize preview usability and creation/editing quality across PPTX, DOCX,
  and XLSX, including supported uploaded files.
- Editable PPTX and HTML presentations are first-class deliverables with
  separate capabilities; neither implies lossless conversion to the other.
- Text, supported shapes, tables, and charts remain native Office objects.
  Images remain images; their internal contents are not editable Office shapes.
- Never deliver full-slide screenshots as an allegedly editable presentation.
  Preview images are separate derived outputs.
- PPTX preview is static initially. Exported decks may include selected,
  verified transitions/animations even though CaberOS does not play them.
  Label this explicitly; preview limitations must not strip source effects.
- HTML presentations have isolated live playback, including supported motion
  and interaction, plus stable slide states for thumbnails and visual review.
- Formula authoring/editing is included: store actual Excel formulas, not
  formula-looking text. Formula calculation inside CaberOS is a separate
  decision; unevaluated or cached values must not masquerade as fresh results.
- Native Office editing is verified in PowerPoint/Word/Excel. Further manual design
  can happen there or in Canva, subject to Canva's import compatibility; CaberOS
  does not promise equivalent Canva import fidelity or add a Canva integration.
- A Canva-like built-in workspace is a future direction, not v0.2.2 scope.

## Release Boundary

### Included

1. Revision-bound rendering foundation for generated DOCX/PPTX, with explicit
   renderer identity, readiness, warnings, failure states, and bounded work.
2. Better shared preview navigation: slide/page thumbnails, zoom, fit modes,
   keyboard navigation, expanded viewing, and responsive layouts.
3. Native editable presentation design: themes, reusable layouts, typography,
   shapes, images, tables, charts, notes, and predictable placement.
4. Styled document authoring: covers, heading hierarchy, paragraph/list/table
   styles, images/captions, page settings, headers/footers, and page numbering.
5. Revision-bound visual inspection available to the agent, followed by a
   bounded inspect-and-fix workflow with honest verification reporting.
6. Targeted conversational revision of slides, document sections, and workbook
   sheets/ranges, preserving editability, unaffected content, provenance, and
   conflict detection.
7. Representative quality fixtures, actual Microsoft PowerPoint/Word/Excel checks,
   documentation in both locales, changelog, and packaged release verification.
8. Existing white-backed desktop icon, verified in packaged macOS/Windows builds.
9. First-class HTML presentation creation, revision, portable download, and
   isolated in-app playback with supported transitions/animations and interaction.
10. Scoped PPTX/DOCX template support: explicitly supported masters/layouts/styles
    with validation and unsupported-feature warnings, not universal template import.
11. Selected PPTX transitions/animations with native PowerPoint playback checks;
    preserve effects through supported edits or warn/refuse before losing them.
12. XLSX creation/editing with fills, borders, alignment/wrapping, fonts, number
    formats, row/column sizing, merged cells, freeze/filter, native tables/charts,
    and a defined subset of conditional formatting and data validation.
13. Safe uploaded-workbook adoption and targeted edits, including real formulas,
    with preflight preservation checks, original revision retention, and
    warnings/refusal for unsupported features.

PPTX/DOCX/XLSX creation/editing and HTML presentations are the authoring focus.
Keep existing PDF/media/text preview and artifact behavior working. Imported
Office files get scoped editing and best-effort previews with unsupported
features reported; universal lossless editing is not promised.

### Explicitly Deferred

- Canva-style drag/drop editing, collaborative canvas, template marketplace,
  brand-management product, and agent-authored CaberOS apps.
- Universal Office template compatibility and lossless editing of arbitrary
  imported documents. Supported template subsets are included.
- SmartArt creation, macro execution, embedded executable-object execution/
  editing, and advanced manual Office editing as an in-app product.
- PPTX animation playback inside CaberOS, exhaustive Office effect support,
  and lossless HTML-to-PPTX conversion.
- Public Office-to-PDF export, unless separately approved; preview conversion
  does not automatically authorize a new export capability.
- Universal Excel feature/formula-engine compatibility and arbitrary PDF editing.
  In-app recalculation is undecided, not a prerequisite for formula authoring.
- Connected Knowledge/cloud drives/external retrieval, generic Tasks/events,
  channel approvals, remote terminal drivers, persistent-agent handoff,
  realtime Voice Mode, and video generation.
- Broad dashboard redesign and rewriting the artifact subsystem.

Earlier roadmap references to "v0.2.2 and later" do not commit all deferred items
to this release. No release date or provider/runtime choice is assumed.

## Non-Negotiable Invariants

1. Native editability is tested on exported Office bytes, not inferred from a
   successful parser reopen or an attractive preview.
2. Source artifact revisions are authoritative. Renders are disposable,
   revision-bound derivatives and never mutate Office files.
3. Chat opens the referenced revision; Workspace opens the proven current file.
   A new revision never silently replaces the version being inspected.
4. Content extraction, layout rendering, structural validation, and visual
   review are distinct outcomes. None is silently substituted for another.
5. Preview fidelity is relative to a named renderer, not a promise of pixel
   identity with every PowerPoint/Word version. Font substitution is visible.
6. Artifact and agent-facing rendering operations cross syscall mediation.
   Operator preview uses authenticated APIs with existing ownership checks.
7. Office rendering cannot run macros, document scripts, remote-resource fetches,
   or embedded executables. HTML deck scripts run only in an isolated, untrusted
   presentation surface with no CaberOS credentials/API authority, host access,
   or implicit network access. Work, output, and process lifetime are bounded.
8. No automatic runtime/font downloads or document egress. Optional installation
   uses the existing consent/readiness model; no paid or remote fallback.
9. Memory, skills, templates, and tool configuration never expand authority.
   Model calls and asset generation retain normal accounting and provenance.
10. External edits are never silently overwritten. Restore remains append-only.
11. Static PPTX previews neither verify playback nor justify removing effects.
    Supported revisions preserve existing effects; when preservation cannot be
    guaranteed, warn and refuse the destructive edit or request explicit consent
    for a clearly identified reduced-feature copy, never silent flattening.
12. Workbook formulas and their results are distinct. Report result provenance
    as unevaluated, cached, or freshly calculated by a named engine. Missing
    results are not zero; uploaded formulas are untrusted and never implicitly
    trigger external links, network fetches, macros, or executable actions.

## Decisions Required Before Implementation

| Decision | Proposed default | Gate |
|---|---|---|
| Layout renderer | Evaluate local rendering against representative files on macOS, Windows, Docker | Select only after fidelity, safety, packaging, license, and resource tests |
| Office conversion | Revisit preview-only conversion explicitly; no public PDF export | Prior exclusion is not overturned by this plan |
| Runtime distribution | Existing optional dependency/consent flow; no required Microsoft Office installation | State install size, offline behavior, updates, and degraded mode |
| Fonts | Small explicitly licensed baseline; document substitutions and Office portability | No silent system install or unlicensed font embedding |
| Authoring contract | Extend current structured specs/ops with validated layout/style primitives | Preserve old specs; choose identity and revision addressing before UI work |
| HTML artifact/playback | Self-contained or bundled local assets, isolated live view, stable capture states | Decide packaging, script/network policy, revision asset pinning, and browser/Tauri isolation before implementation |
| Templates and PPTX effects | Named tested template subset and small native effect vocabulary | Record supported masters/styles/effects and verify Office playback independently of static preview |
| XLSX scope/preservation | Named style, chart, table, validation and conditional-formatting subsets | Preflight imported features; preserve supported objects and warn/refuse destructive round trips |
| Formula calculation | Formula authoring included; no in-app evaluation assumed | Decide whether to add a bounded local engine; document supported functions, cache freshness, security and runtime costs before claiming calculated results |
| Agent visual input | Reuse supported image input under the admitted model's authority | No vision model means visual review is unavailable, not passed |
| Initial quality bar | Curated deck/report examples and a written human-review rubric | Operator reviews examples before implementation is called complete |

A renderer evaluation is a decision gate, not permission to download software
or send documents to a third party. If no acceptable renderer is found, revise
the release scope explicitly; do not relabel content extraction as rendered pages.

work in W4 depends on W1; HTML playback depends on W2H's isolation contract.

Office slide, one live HTML slide, one styled document page, and one styled
formula-bearing sheet end to end before expanding the layout/style catalog.

## Release Gate

- Complete the [acceptance matrix](v0.2.2/acceptance-matrix.md), with pass/fail/
  blocked/skipped recorded separately and evidence tied to a commit.
- Run backend Ruff/format/full pytest and frontend lint/test/build gates.
- Browser-verify shared panel surfaces, revision switching, failure states,
  responsive behavior, and conversational revision with isolated QA data.
- Verify representative files in actual Microsoft PowerPoint, Word, and Excel; record
  application versions, OS, fonts, edit operations, and any layout differences.
- Verify selected PPTX effects in PowerPoint, separately from static previews,
  and preservation during supported edits. Verify HTML motion/interaction and
  portable downloads in supported browsers with network access disabled.
- Verify Excel formula authoring, edit/recalculate/save/reopen, uploaded workbook
  preservation, and formula-result provenance in CaberOS separately. If no
  in-app engine is selected, show formula/cached/unavailable states honestly.
- Verify rendering/runtime readiness in packaged macOS, Windows, and Docker.
  Source-mode success is not packaged-runtime evidence.
- Bound packaged-gateway and renderer smoke tests with timeouts, diagnostics,
  and process cleanup; diagnose any outstanding v0.2.1 smoke hang from evidence.
- Update README, technical/product references, built-in skill resources,
  English/Vietnamese official docs, and `CHANGELOG.md` before tagging.
- Bump manifests through the established release process only after acceptance.
  Do not move the v0.2.1 tag or change its release artifacts for this work.

Planning does not authorize a commit or push. Ask before each coherent commit
and push; keep unrelated operator edits intact.
