# v0.2.0 Release Plan — Agent Workbench

**Release sequence:** `v0.1.9` → `v0.2.0` → `v0.2.1` → `v0.2.2`
**Status:** planned
**Integration branch:** `feat/v0.2.0`
**Headline:** agents that plan complex work, research through a browser, and deliver versioned professional artifacts

---

## Product promise

By v0.2.0, a user can ask a CaberOS agent to plan a substantial task, inspect and approve the plan, let the agent research dynamic websites, and receive DOCX, PPTX, XLSX, and PDF artifacts that can be previewed and revised without leaving CaberOS. Skills become a managed, versioned library; scheduled work is reliable; and native/browser notifications request attention only when the relevant work is not already visible.

Representative outcome:

> Plan a quarterly market analysis, research current sources in an isolated or approved persistent browser profile, use local Vault evidence, generate an XLSX analysis plus PPTX and PDF report, preserve every artifact revision, and notify me when the scheduled run needs attention or completes.

v0.2.0 deepens CaberOS as a local-first Agent Operating System. It does not turn CaberOS into a plugin for Claude, Cursor, or another agent host.

## Release boundary

### Included

1. Artifact Studio: DOCX/PPTX/XLSX generation, PDF export, validation, conflict handling, and immutable revision history.
2. File previews: clipboard image paste, visual composer attachments, chat right-side preview, Agent Settings → Workspace split preview, and Skill-resource preview.
3. Browser automation: managed first-use browser runtime, headless/visible modes, isolated defaults, opt-in persistent profiles, approvals, and traceable evidence.
4. Plan Mode: built-in `/plan`, syscall-enforced read-only planning, revisions, approval, execution, progress, and deviation handling.
5. Skills Studio: built-in/global/agent scopes, one managed page, agent-assisted draft creation, validation, publication, assignment, and revisions.
6. RAG v2 foundation: FTS correctness, embedding-model setting, local hybrid retrieval, parent/child chunks, diagnostics, health, and atomic re-index.
7. Scheduler v2: one-time/interval/cron, timezone/DST, missed-run, overlap, retry, approval, and history semantics.
8. Notifications v2: in-app/browser/Tauri delivery, exact-related-view suppression, deep links, and deduplication.
9. Background terminals: true async start, incremental output, ownership, timeout/cancellation, and complete process cleanup.
10. Observability/reliability: Execution Manifests, per-model-call provider accounting, clear tool states, packaging fixes, clean installation, and signed update verification.

### Explicitly deferred

- OneDrive, SharePoint, Google Drive, Qdrant, and external Retrieval Resources (`v0.2.1`)
- SQL/database Knowledge Sources
- Generic Tasks and event-driven automation (`v0.2.2`)
- Inline channel approval/elicitation (`v0.2.2`)
- Docker/remote/per-agent execution environments
- Persistent multi-agent Missions
- Agent marketplace and executable plugin SDK
- CLI/TUI without a concrete workflow
- CaberCore extraction solely for architectural purity
- Agents exposed as MCP tools inside another agent host
- Additional desktop platforms without verified sandbox behavior
- Arbitrary PDF editing, Office macros, and perfect Office-aware diffs

## Non-negotiable invariants

1. A conversation advances strictly as `reason → act → observe → repeat`. Multiple tool calls emitted in one model turn may execute concurrently within that action step; separate reasoning steps never run concurrently in the same conversation.
2. FastAPI remains a gateway layer for browser, Tauri, channels, and future adapters.
3. Plan Mode is restricted by syscall mediation, not merely a prompt.
4. Skills and Plans never widen capability authority.
5. Browser pages, downloads, imported Skills, and retrieved documents are untrusted content.
6. Approved Plans, published Skills, Artifacts, Schedules, and Retrieval Profiles use immutable revisions captured by an Execution Manifest.
7. Local-first is the default; egress, persistent login state, remote models, and external writes remain explicit and auditable.
8. Source documents are authoritative and derived indexes are rebuildable.
9. Degraded behavior is reported honestly; CaberOS never claims a renderer, browser, or semantic-retrieval stage succeeded when it did not.
10. User data lives in managed application data and survives application/image updates.

## Branch and pull-request strategy

`feat/v0.2.0` is the release integration branch. Each pillar branch starts from its latest compatible integration commit and opens a PR back to `feat/v0.2.0`.

```text
origin/main
    ↓
feat/v0.2.0
    ↑
    ├── feat/v0.2-foundation
    ├── feat/v0.2-artifacts
    ├── feat/v0.2-browser
    └── ...
```

Pillar work uses small logical commits and may use several PRs when doing so preserves a coherent tested outcome. Keep `main` releasable while v0.2 integration is incomplete. Merge relevant main hotfixes into the integration branch and rerun affected gates.

Before final integration:

1. Move every workstream to Verified.
2. Run the full release gate on `feat/v0.2.0`.
3. Commit the `0.2.0` manifest bump on the integration branch.
4. Open the final protected-main PR from `feat/v0.2.0` to `main`.
5. After merge, verify `origin/main` contains the exact approved code/version.
6. Run the protected-main release script phase that tags the merge commit.
7. Verify the remote tag dereferences to that commit before trusting release artifacts.

## Integrated acceptance stories

### Plan, research, and produce

1. User enters `/plan Create a quarterly market analysis presentation`.
2. Agent inspects workspace, Vault, Skills, and browser sources without mutating state.
3. Plan declares inputs, capabilities, browser profile, steps, expected XLSX/PPTX/PDF outputs, approvals, verification, and completion criteria.
4. User revises and approves the Plan.
5. Agent executes sequentially, researches a JavaScript site, and creates the artifacts.
6. User opens the exact message revision in the chat right-side preview and the current file in Agent Settings → Workspace.
7. User requests a revision; history preserves both versions.
8. Trace shows the Execution Manifest, model calls, sources, browser actions, approvals, Plan Steps, and Artifact revisions.

### Managed browser

1. A Safari-only clean desktop installs and verifies the managed browser runtime on first use.
2. Public research runs headlessly in an isolated profile.
3. Operator creates a persistent profile and signs in through visible mode without exposing credentials to the model.
4. Out-of-scope redirects and external writes pause.
5. Another run queues instead of sharing the profile concurrently.
6. CaberOS update reuses a compatible runtime and preserves profile state.

### Skill creation

1. User presses Create Skill.
2. Skill Builder generates a restricted draft after eliciting purpose, resources, capabilities, examples, and failures.
3. Operator previews resources, reviews validation/diff, and publishes globally for selected agents.
4. An agent-local Skill can visibly shadow it.
5. Updating the global revision does not change an active run.

### Hybrid local knowledge

1. User configures and validates an embedding model.
2. Vault builds a local vector generation while FTS remains available.
3. Retrieval fuses lexical/semantic candidates and exposes its trace.
4. Vector failure degrades honestly to FTS according to profile policy.
5. Embedding dimension change rebuilds and atomically activates a new generation.

### Scheduled work and notification

1. User schedules an approved Plan in a named timezone.
2. Sleep/restart and overlap follow configured policy.
3. A gated action pauses and creates one attention request.
4. Exact focused view suppresses toast/browser/system delivery while updating inline.
5. Approval resumes execution and completed Artifacts link to Schedule history.

### Long-running terminal

1. Agent starts `terminal(async=true)` and receives an ID immediately.
2. Repeated reads return only incremental output.
3. Completion returns final output and exit code.
4. Closing another command terminates its child process.
5. Run cancellation/gateway exit leaves no orphan and records interruption.

## Migration contract

- Create a restore point before v0.2 schema migration.
- Preserve v0.1.9 agents, sessions, messages, runs, audit, Vault, credentials, workspaces, schedules, and notifications.
- Separate built-in, global, and agent-local Skills without content loss or authority expansion.
- Preserve existing citations; rebuild only derived indexes.
- Embeddings remain optional and FTS-only behavior continues without setup.
- Preserve Artifact history and browser-profile data across desktop/Docker updates.
- Failed migration leaves prior state recoverable.

Detailed migration and verification behavior is owned by the relevant feature plan and the observability/release plan.

## Verification policy

Every behavior-changing feature follows red → green → refactor:

1. Add a failing test for observable behavior.
2. Confirm expected failure.
3. Implement the smallest correct behavior.
4. Run focused tests.
5. Refactor under coverage.
6. Run pillar and integration gates.

Baseline automated verification:

```bash
cd backend && uv run pytest -v
cd backend && uv run ruff check src/ tests/
cd backend && uv run ruff format --check src/ tests/
cd frontend && npm run lint
cd frontend && npm test
cd frontend && npm run build
cd frontend/src-tauri && cargo test
cd frontend/src-tauri && cargo check
```

Also require existing Playwright frontend E2E verification, packaged-runtime tests, security tests, Docker parity, clean desktop installation, v0.1.9 upgrade, and signed updater smoke.

## v0.2.0 release gate

The tag is blocked until:

- Every workstream is Verified against the integration branch.
- Full backend, frontend, Rust/Tauri, packaged-runtime, security, and CodeQL checks pass.
- Clean macOS ARM64 installation and v0.1.9 migration/restore/update pass.
- DOCX/PPTX/XLSX/PDF generation, preview, conflict, history, restore, and export pass.
- Composer paste and chat/Workspace/Skill preview behavior pass responsively and accessibly.
- Managed browser installation, isolated/persistent profiles, visible takeover, authority, and Docker parity pass.
- Plan Mode read-only enforcement, revisions, approval, execution, and deviation handling pass.
- Skills Studio scope, storage, builder, validation, assignment, shadowing, and history pass.
- Local hybrid retrieval, citation integrity, atomic rebuild, and FTS fallback pass.
- Background terminal output, ownership, completion, timeout, cancellation, and process cleanup pass.
- Scheduler restart/DST/overlap/retry/approval behavior passes.
- Native/browser notifications deduplicate and suppress exact visible work.
- Per-model-call accounting reconciles with run totals and tool statuses are accurate.
- The manually exercised integrated acceptance stories pass with real models.
- Documentation states actual supported behavior and limitations.
- The release tag is pushed only after all version manifests agree and points to the verified merge commit.

A calendar target is never permission to tag a broken artifact.

## Roadmap after v0.2.0

- Richer Artifact collaboration and Office-aware comparison
- Multi-operator support
