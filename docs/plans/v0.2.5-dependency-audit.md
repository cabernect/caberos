# v0.2.5 Dependency Audit

Audited on 2026-11-25 against the release-preparation dependency lockfiles.
This is release preparation, not a claim that the application has no
vulnerabilities. Audits only cover advisories known to their databases.

## Changes

| Area | Change | Reason |
| --- | --- | --- |
| Frontend | Remove unused `shadcn` CLI | No source imports or package scripts use it. Removes its dependency tree, including the reported Hono and minimatch findings, without incompatible transitive overrides. Generated UI components remain unchanged. |
| Backend | Soup Sieve 2.9.1 -> 4.1.3 | Resolves four selector parsing/matching resource-exhaustion advisories. Beautiful Soup's declared dependency range permits this version; the backend suite is the compatibility gate. |
| Website | Astro 7.3.3 -> 7.4.13 | Resolves attribute injection and image-endpoint path containment advisories. Its dependency tree requires Node.js >=22.23.4; update `.node-version` and package engines together. |
| Desktop | cookie 0.18.2 -> 0.18.3 | RUSTSEC-2026-0594, private-cookie nonce reuse after fork. CaberOS does not enable private cookies, but the compatible patch removes the affected version. |
| Desktop | url 2.5.8 -> 2.5.9 | RUSTSEC-2026-0592, stack overflow on nested blob URL origins. Also updates form_urlencoded to 1.2.3. |
| Desktop | rustix 1.1.4 -> 1.1.6 | RUSTSEC-2026-0486, unsound extended-attribute buffer handling. |

No broad backend or desktop dependency upgrade was performed.

## Reproduction

```bash
# Frontend and website, separately
npm audit

# Backend, including optional Postgres and development dependencies
uv export --frozen --all-extras --no-emit-project --format requirements-txt \
  | uvx pip-audit --disable-pip --no-deps -r /dev/stdin

# Desktop, all packages in Cargo.lock
cargo audit
```

After the changes, npm reports zero vulnerabilities for both projects and
pip-audit reports no known vulnerabilities. Cargo reports zero entries in
its vulnerability list, but still reports the informational findings below.
No advisory suppressions were added.

## Remaining Rust Findings

- `glib` 0.18.5: RUSTSEC-2024-0429 is an unsound iterator implementation,
  fixed in >=0.20. This version belongs to Tauri's Linux GTK3/WebKit chain.
  `cargo tree --target all -i glib@0.18.5` traces it through GTK 0.18 and
  WebKit2GTK. A forced 0.20 override would not satisfy their 0.18 dependency
  contracts. It is not part of the macOS/Windows release targets; Linux
  source builds retain the finding pending an upstream framework migration.
- Unmaintained-package notices remain for `chrono` (RUSTSEC-2026-0543),
  `proc-macro-error` (RUSTSEC-2024-0370), `zbus_names`
  (RUSTSEC-2026-0371), `zvariant` (RUSTSEC-2026-0370), and
  `zvariant_derive` (RUSTSEC-2026-0372). These are upstream lockfile
  dependencies, not findings resolved by a compatible patch. Replacing the
  desktop framework/notification stack is outside this cleanup release.

### Upstream Recheck

The remaining reports were investigated again rather than treating an
informational classification as proof of safety:

- The registry's newest stable Tauri 2.12.7 still depends on GTK `^0.18`.
  The newest non-yanked GLib 0.18 release is 0.18.5, so updating Tauri
  within version 2 does not resolve RUSTSEC-2024-0429. A real fix requires
  a tested GLib backport/fork or an upstream GTK-stack migration, not
  forcing incompatible versions into the lockfile.
- The newest stable opener plugin 2.7.3 still requires zbus `^5.9`;
  notification plugin 2.8.1 also requires zbus `^5`. Those dependency
  contracts retain the standalone zvariant/zbus_names packages. Their
  maintenance advisories list no patched versions; upstream recommends
  migrating to zbus 6, where the wire-format code is integrated.
- A trial update to notify-rust 4.19.0 introduced zbus 6 alongside zbus 5,
  rather than eliminating the old chain. The trial and its incidental
  lockfile changes were rolled back; no extra D-Bus stack is retained.
- `cargo tree --target all --all-features -i chrono` reports no active
  dependency path. The lockfile retains it as an optional dependency of
  serde_with. Removing its lockfile entry by hand would not migrate that
  upstream optional integration.

These findings remain visible. No audit ignores, package-version disguises,
alpha framework upgrades, or untested vendored security patches were added.

## Release Boundary

Version manifests and product entries in npm, uv, and Cargo lockfiles must
all agree on 0.2.5. Run `scripts/check-version.sh` and inspect the lockfile
product entries before committing. No tag or publication is part of this audit.

## Local Validation

- Backend: 2,006 passed, four opt-in sandbox tests skipped; Ruff lint and
  formatting pass. Existing dependency/test-teardown warnings remain.
- Frontend: 317 tests pass; lint and production build pass with existing
  lint and bundle-size warnings.
- Desktop: `cargo test --locked` passes all four macOS Rust tests; no
  packaged updater installation or Windows runtime test is claimed.
- Website: locale coverage, Astro checks and 63-page static build pass
  on Node.js 22.23.4. Existing missing-collection/404 build warnings remain.
- Version check, npm/uv/Cargo product lockfile checks and release-note
  extraction pass.
- Validation exposed a slideshow mount-reset race. Existing reveal tests
  failed in two full-suite runs but passed alone. Moving the source reset
  from a passive effect to a layout effect prevents it from undoing an
  immediate Slideshow click; the full suite then passes. Chromium also
  verifies open, click reveal, slide navigation and Escape exit using the
  real preview components with an in-memory backend, without touching
  application data.
