## 2. Redesign

### 2.1 What is wrong today (measured)

| Finding | Evidence |
|---|---|
| No mobile shell | At a true 390 px width the 240 px sidebar stays open; content gets ~150 px, "New Agent" is clipped, cards are cut off, the onboarding card covers the sidebar |
| Desktop-only by construction | 19,244 UI lines but 17 `sm:/md:/lg:` classes, 1 `@media`, 1 container rule |
| Viewport grids ignore containers | Known root cause of the "squeezed columns" bug (W13 notes) |
| Page monoliths | `ProvidersSettings` 3,071, `Conversation` 2,077, `SettingsOverlay` 1,679, `Mcps` 1,501, `Scheduler` 1,433 lines |
| Token drift, dark mode by remediation | W13 inventory (`--white` vs `--surface`, rgba() literals) |
| Desktop window can't go narrow | `minWidth: 960`; fine for desktop, irrelevant for web |
| macOS is a stock window | No title-bar treatment, no native menu, no notifications |
| Release matrix | `darwin-aarch64` + `windows-x86_64` only: no Intel Mac, no Linux desktop |

### 2.2 Information architecture

Today the sidebar is a feature list (11 destinations, three groups). Proposal: five
destinations organised by what the operator is trying to do, not by implementation.

```text
TODAY                                  PROPOSED
Agents                                 Home        ← attention-first (new default)
Scheduler                              Agents      ← chat-first; Caber is the default entry
─ MCPs                                 Library     ← Skills · MCPs · Knowledge · Channels (tabs)
─ Skills                               Automations ← Schedules · Plans · Heartbeats
─ Channels                             Activity    ← Runs/Traces · Overview · Notifications
─ Knowledge Vault
─ Overview / Traces
Notifications, Settings                Settings (kept, but a page, not an overlay on mobile)
```

**Home** answers "what needs me?" in one screen: pending approvals and elicitations,
running agents, scheduled runs that failed, newly finished artifacts. Today this is
scattered across a notification bell, chat pages and the scheduler.

A global **command palette** (⌘K / Ctrl+K, and a search button on mobile) replaces
deep navigation for power users: jump to agent, open artifact, run skill, approve.

### 2.3 Adaptive shell (one codebase, three form factors)

```text
≥ 1100 px  Desktop     collapsible sidebar (240 ⇄ 64) · right dock for preview/detail
 700–1099  Tablet/     icon rail (64) · dock becomes overlay drawer
           narrow win
 < 700     Phone       bottom tab bar (Home · Agents · Library · Activity · More)
                       full-screen routes · dock becomes bottom sheet · 44 px targets
                       safe-area insets · composer pinned above the keyboard
```

Rules (decisions in §6):

- **One layout rule:** components size from their *container* (Tailwind v4 `@container`
  utilities are native), the *shell* switches by viewport. This is the fix W13 asked for.
- Touch targets ≥ 44 px, visible focus rings, keyboard reachable, `prefers-reduced-motion`.
- Tables become stacked cards below 700 px; modals become full-screen sheets on phone.
- Conversation's preview dock: docked ≥ 1100, drawer 700–1099, bottom sheet < 700.

### 2.4 Design system

- **Semantic surface tokens** (page / card / dock / overlay / accent-soft / danger-soft) with
  a *designed* dark palette per role. One sweep removes stray `--white` and rgba literals.
- **Shared primitives** extending the existing `components/ui` (button, card, input,
  textarea): `Toolbar`, `FilterPills`, `SearchRow`, `CardGrid`, `DetailDrawer/Sheet`,
  `EmptyState`, `Badge`, `Modal/Sheet`, `ListDetail`.
- **Size budget:** no page component over ~500 lines; Conversation splits into data/SSE,
  composer, preview dock, timeline.
- Not a rebrand: keep the warm palette, logo and typography.

## 3. v0.3.0 product thesis

> v0.2 gave agents hands. v0.3 lets the operator **supervise them from anywhere**.

The product's unfair advantage is local-first: the agent runs on the operator's machine
with their files and tools. Its weakness is that supervision requires sitting at that
machine. Scheduled agents hit approval gates (v0.2 Scheduler + approvals) and nobody is
there. The big update closes that loop.

### Pillars

| # | Pillar | What the operator gets | Depends on |
|---|---|---|---|
| A | **Design system + adaptive shell** | The same app on phone, tablet, desktop, web and Tauri (§2) | none; start now |
| B | **Home / Inbox + command palette** | One screen for "what needs me" (approvals, failures, finished artifacts) | A, W9 |
| C | **Remote companion** | Pair a phone, install as a PWA, get push notifications, approve/deny gates and chat from anywhere | A, B, W9 |
| D | **Plan Mode as a first-class UI** | `/plan` → inspect → revise → approve → execute with progress | W5 backend |
| E | *Stretch:* **Missions** | Durable multi-agent work with a shared plan | D |

**Cut line:** A + B + C + D is the release. E ships only if A–D are verified early.

### Pillar C: honest scope and threat model

Exposing a local agent platform to a phone is the riskiest item in this plan, so it is
specified narrowly:

- **Transport:** v0.3 documents and tests user-controlled tunnels (Tailscale / Cloudflare
  Tunnel / reverse proxy). A CaberOS-run relay is *not* in v0.3.
- **Pairing:** QR-code device pairing; per-device revocable tokens; HTTPS required for any
  non-localhost origin.
- **Phone capabilities are scoped by default:** view runs, approve/deny, chat, read
  artifacts. No shell, no settings, no provider keys from a paired device unless the
  operator enables each.
- **Audit:** every remote action recorded with the device identity.
- **Not claimed:** end-to-end encryption through a relay, because no relay exists.

### Explicitly not in v0.3

Marketplace/plugin SDK, SQL knowledge sources, CLI/TUI, Linux desktop, Docker execution
environments. Connected Knowledge (v0.2.1) and Tasks/Event automation (v0.2.2) keep their
own releases and are not re-planned here.

## 5. Risks

| Risk | Mitigation |
|---|---|
| Redesign churns pages other workstreams are still editing | Do pillar A tokens/primitives first (additive); migrate pages one PR at a time |
| Remote companion widens attack surface | Narrow scope above; security review is a gate, not a follow-up |
| Responsive work regresses silently | Playwright + axe gate before any page migrates |
| W5 slips and blocks pillar D | D is separable; ship A–C without it if needed |
| macOS cannot be verified from the Windows dev machine | Use the macOS release runner + a clean-install checklist; do not claim verified until run |

---

## 6. Decisions

Settled 2026-10-07:

1. **Order:** finish v0.2.x (W5 Plan Mode backend, W9 native notifications) while the
   design system and adaptive shell proceed in parallel.
2. **Remote companion:** in v0.3, over user-controlled tunnels. No CaberOS relay.
3. **Intel Mac:** not supported; release notes say ARM64-only.
4. **Layout rule:** container queries for components, viewport for the shell.
5. **Component base:** extend the in-house `components/ui`; no Radix migration.

## Unresolved

- Whether W7's recorded failures were fixed in later rounds.
- Actual phone usage expectations (the whole of pillar C assumes operators want it).
- Who owns macOS verification, since it cannot be done from this machine.
