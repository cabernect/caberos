# v0.2.1 - Honest Vault, Workspace & Tools

Status: draft for operator review. Baseline: `main` at `8b0be89`.
This plan is not authorization to implement, commit, push, or publish a release.

Detailed workstreams, dependencies, implementation steps, and verification
scenarios live in [`v0.2.1/README.md`](v0.2.1/README.md).

## Goal And Release Boundary

Complete the existing Honest Vault & Media Tools roadmap while adding two
day-to-day workflows: using an existing repository as an agent workspace and
understanding when manual conversation compaction starts, succeeds, or fails.

The v0.2.0 desktop lifecycle, titlebar spacing, and dragging fixes are already
in the baseline. They are regression checks, not pending v0.2.1 features.

| Workstream | Outcome | Recommended order |
|---|---|---|
| Compaction UX | Unambiguous submission, visible progress and honest results | 1 |
| Agent Workspace Selection | Attach an existing project folder consistently and safely | 2 |
| Vault document inspection | Inspect persisted chunks, locations, and token counts | 3 |
| Tabular row layer | Bounded, inspectable CSV/XLSX row queries | 4 |
| Settings -> Tools | Global Model Offering bindings and search configuration | 5 |
| First media capability | One approved, accounted, artifact-producing workflow | 6 |

All rows are proposed release scope; the order does not silently defer existing
roadmap commitments. If capacity becomes a problem, explicitly revise this
document before cutting scope. No release date is assumed.

## 1. Compaction UX

### Current Evidence

The earlier isolated browser test successfully saved a real summary, reduced
estimated context from 29,829 to 24,452 tokens, and recalled covered facts after
reload. That is evidence for the tested path, not proof of every failure mode.

On the baseline, `Conversation.tsx` displays progress in the message list,
logs request failures to the console, and ignores the response's `error`.
`api.ts` omits that field from its compaction response type. The earlier browser
test also needed one Enter to select autocomplete and another to submit.

### Behavior

- An exact `/compact` followed by Enter executes once. Selecting a partial
  suggestion completes the command without accidentally sending other commands.
  Show a clear submission affordance and preserve IME composition behavior.
- Keep an accessible status immediately above the composer, independent of
  message-list scroll position. Disable duplicate submission while pending.
- Distinguish pending, compacted, unchanged, and failed outcomes. Treat a
  nonempty response `error` as failure even when the HTTP status is successful.
- On success, show before/after context estimates, explicitly labeled as
  estimates. Do not promise a fixed reduction or describe it as billed usage.
- A legitimate no-op says that nothing was compacted; a provider/budget failure
  must not look like successful completion. HTTP failures have visible messages.
- Bind results to the initiating agent/session. Switching conversations while
  waiting must not update another conversation's meter or display its status.
- Preserve the saved summary/coverage contract. Do not rewrite the compaction
  algorithm or add a background job framework merely to improve feedback.

### Small Implementation Units

1. Type the complete response and test success, no-op, response error, and HTTP
   error against scripted results; retain backend persistence regression tests.
2. Add session-scoped pending/result presentation and duplicate-submit guards.
3. Fix exact-command keyboard submission with autocomplete/IME regression tests.
4. Browser-test scrolled history, narrow layout, errors, rapid Enter presses,
   session switching, and reload. Record results separately from old evidence.

## 2. Agent Workspace Selection

### Definitions And Invariants

An agent has a default workspace selection: CaberOS-managed or an explicitly
authorized existing directory. A session pins a workspace location; a run uses
that session's location. A pin preserves location, not a snapshot of file bytes.

- Attach only: never copy, move, initialize, or delete repository files on
  selection. Do not create a missing external directory automatically.
- Multiple agents may select the same directory with independent operator
  authorization. Shared files do not share identity, credentials, memory, or
  permissions, and do not provide automatic concurrent-edit coordination.
- Keep identity, MEMORY.md, credentials, and platform-owned configuration in
  managed storage. Audit agent-local skills/drafts so they do not unexpectedly
  migrate into a selected repository or become inaccessible.
- Canonicalize and validate external directories. Reject unavailable or denied
  paths explicitly; never silently fall back to the managed workspace.
- Keep strict containment, including traversal and symlink checks. Selecting a
  folder does not enable open sandbox mode or grant unrelated capability access.
- A path is on the gateway's host, not necessarily the browser's machine.
  Desktop gets a native chooser; web gets explicit host-path entry and
  validation. Docker can select only directories already mounted in its host
  namespace; do not imply a browser folder picker grants backend access.

### Workspace Resolution Module

Place selection validation, managed-directory creation, session pinning, and
root resolution behind one small interface in the workspace module. Callers
must not independently interpret `config.workspace` or construct default roots.
Avoid a plugin architecture or multiple interchangeable resolvers.

The current pipeline honors `config.workspace`, while workspace browsing and
previews create the default directory. Artifacts currently use an agent id as
`workspace_id`; simply changing the root would reinterpret historical paths.
Resolve that identity contract before exposing selection in Settings.

### Switching And Compatibility

- Changing the default affects new sessions only; old sessions retain their
  workspace. Show the pinned path in conversations and the new-session default
  in Agent Settings so this difference is visible.
- Reject default changes while the agent has in-flight work, including runs
  awaiting approval. Coordinate the check with run admission; a UI-only guard
  or an unlocked check-then-write is insufficient.
- Every run producer must honor the same rule: dashboard, channels, schedules,
  reflection, and sub-agents. Persistent channel sessions do not silently
  switch roots after a default change.
- Bind attachment metadata and artifact live paths to their original workspace.
  Exact artifact revision bytes remain in managed storage. Restoring or adopting
  must validate the intended root, not reinterpret paths under the new default.
- Audit agent deletion and cleanup: no attached directory or its contents may
  be removed as a consequence of deleting an agent or workspace selection.
- Before rollout, decide how legacy unpinned sessions are backfilled. Where old
  configuration/history does not prove a location, do not guess: surface an
  explicit repair/confirmation path and preserve existing records.

### Small Implementation Units

1. Inventory all workspace consumers and define persistent workspace identity,
   session/run pins, artifact compatibility, and legacy migration tests.
2. Implement the workspace module and additive DB migration; preserve managed
   behavior with external selection still hidden.
3. Route execution, terminal, uploads, browsing, previews, artifact mutations,
   and other run producers through the same pinned resolution.
4. Add authenticated selection/validation and atomic active-work rejection.
   Agent-provided config/import paths must not bypass operator authorization.
5. Add Agent Settings selection, access confirmation, resolved-path display,
   and conversation path display; only expose it after the prior units pass.
6. Verify repo paths with spaces/non-ASCII, restart persistence, unavailable
   folders, permission failures, symlinks, old references, and deletion safety.
   Exercise native selection on desktop as well as web host-path entry.

## 3. Existing Vault Scope

### Document Inspection

Provide an authenticated, paged document-chunk interface and a chunk-tree view:
kind, parent/child relationship, source location, token count, and bounded text.
Inspection identifies canonical corpus state separately from derived embedding
generation membership. Generations are not historical chunk-text snapshots.
Do not invent source coordinates. Test ownership, pagination, corpus changes,
empty documents, rebuilds, and failed/stale generations.

### Tabular Row Layer

Materialize CSV/XLSX row records with sheet/row/cell provenance and searchable
row text. Separate row filtering/counting/aggregation from top-k prose retrieval.
Bound ingestion, paging, and model context; if results exceed those bounds,
report truncation or require narrowing rather than claiming a complete answer.

Keep upload refusal until extraction, persisted row queries, agent tools, and
inspection work end to end. Test multi-sheet data, CSV quoting/encoding,
empty/duplicate headers, formulas versus cached values, large inputs, complete
matching-set counts, and citation accuracy. Do not execute spreadsheet formulas.

## 4. Tools And First Media Capability

- Global Settings -> Tools owns capability bindings to Model Offerings
  (provider + model); move search configuration without losing existing values.
- Unconfigured capabilities do not load. A binding never grants an agent
  capability authority or skips approval/egress policy.
- Implement one media slice, not TTS and image generation together.
  Recommendation: TTS first, subject to confirming an already supported provider
  and response format before implementation.
- Output is a tracked, previewable/downloadable audio artifact. Define that
  artifact kind explicitly; the current structured Office formats are not an
  implicit audio contract.
- Record modality units and price provenance in `model_calls`; unknown prices
  remain unknown. Test approvals, denied/unconfigured access, provider failures,
  bounded output, artifact persistence, and ledger correlation.
- STT, image, and video bindings may be documented as planned, but do not render
  nonfunctional controls as supported capabilities.

## 5. Security Follow-Ups

Define private-network policy for `web_fetch` and `browser_open`, including
redirects, DNS/IP handling, loopback, and intended local-service exceptions.
Keep exceptions operator-controlled and tested. Review MCP OAuth/OIDC discovery
and endpoint validation before claiming that follow-up is complete.

Security findings that permit authority expansion block affected workstreams;
they are not optional cleanup after release.

## Release Gates And Non-Goals

- Backend: Ruff lint and format checks plus the full pytest suite.
- Frontend: lint, production build/type checking, and the full test suite.
- Changed desktop code: Rust tests and local packaged-app build; verify native
  chooser/dragging/lifecycle on desktop rather than inferring from DOM tests.
- Browser verification uses isolated QA data/ports; never replace the normal
  development database. Scripted providers cover failure paths. Real-provider
  QA requires explicit consent and records cost/egress expectations.
- Record migrations, compatibility decisions, and actual test results before
  enabling features. Update technical/product docs and release notes to match
  shipped behavior, not aspirations.

Deferred: CaberOS Apps runtime/App Studio, npm launcher, workspace relocation,
multiple mounted roots per session, automatic permission escalation, and broad
frontend redesign. Rendered HTML/Office previews retain their separate roadmap.

Operator-initiated `/handoff` to an existing agent is deferred to v0.2.2 or
later, not committed to v0.2.2. Shared workspaces and existing temporary
sub-agents do not imply persistent agent-to-agent delegation.

Before implementation, confirm the proposed order, choose the first media
capability, and settle ambiguous legacy-workspace migration behavior. Workspace
identity and artifact compatibility are a design gate, not deferred polish.
