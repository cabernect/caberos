### Follow-Up: Clarified Best-Effort Preview Scope

The same command set was rerun after adding preview capability regression checks:
**130 tests passed in 25.82s**; Ruff passed and **341 files** passed the formatting
check. This supersedes the earlier 106-test run for the current local worktree.
Corpus bytes/manifest hash did not change.

Additional checks establish:

- All 11 Office fixture inputs return supported content via `preview_bytes`
  while subprocess launch is prohibited in the test.
- The bytes-to-payload module behaves identically for uploaded/generated filename
  variants apart from the display name. This is extraction evidence, not a new
  HTTP upload or end-user browser test.
- Deck text/chart/table/image/notes, report content and workbook formulas remain
  available; DOCX extraction does not invent a Word page count.
- Three malformed Office inputs return parse errors, distinct from supported
  limited content.
- Nine non-Office/source-mode cases retain classification; the existing preview
  suite also covers PDF page viewing, authentication and revision behavior.

The [preview contract](preview-contract.md) defines persistent limitation alerts.
No visible alert or new production preview metadata has been implemented in
this W0 pass. Those require W1/W4 code and real-browser checks.
